# Component Addition Checklist

This checklist is for adding new components to this Stencil library while keeping Vue/React consumers stable.

## 1. Add the Stencil component

- Create component source under `src/components/<tag-name>/`.
- Add props/events in the component TSX file.
- Keep event names framework-friendly:
  - Prefer kebab-case custom DOM event names when possible.
  - If Vue `v-model` is needed, define a clear update event and value prop.

## 2. Decide Shadow DOM strategy early

- If the component has internal fixed structure plus slot/children text (for example button-like components), prefer `shadow: true`.
- If `shadow: false`, React can overwrite host light DOM children during re-render in some patterns.

## 3. Build once and let generated layers update

Run:

```bash
npm run build
```

This regenerates:

- `output/generated/react/generated/**`
- `output/generated/vue/generated/**`
- `output/react/**`
- `output/react-cjs/**`
- `output/vue/**`
- `output/vue-cjs/**`
- `dist/**`
- typed declarations

Do not hand-edit generated files.

## 4. When you DO need manual adapter changes

### React adapter (`output/generated/react/index.ts`)

Only edit when you want ergonomics beyond raw CustomEvent APIs, for example:

- Add `value` / `onValueChange` wrapper helpers.
- Keep generated component exports, then override specific components in the default export.

### Vue output config (`stencil.config.ts`)

Only edit when component needs `v-model` mapping:

- Add/extend `vueOutputTarget.componentModels` entry:
  - `elements`
  - `event`
  - `targetAttr`
  - optional `eventAttr` (usually `detail`)

## 5. Consumer validation (required)

After component changes, validate both apps:

```bash
# library
cd @mache-hangar/components && npm run build

# react consumer
cd ../wt-ui-react && npm run build

# vue consumer
cd ../wt-ui-vue && npm run build
```

## 6. Event payload rule

- Stencil `EventEmitter<T>` dispatches `CustomEvent<T>`.
- Consumer callback receives the event object.
- Business value is `event.detail` unless adapter explicitly unwraps it.

## 7. Safe defaults for future components

- Keep `output/generated/react/index.ts` and `output/generated/vue/index.ts` as stable adapter entry points.
- Keep `output/generated/**` as read-only source generated by Stencil.
- Treat `output/**` as compiled adapter artifacts.
- Add special adapter logic only for components that need framework-specific UX.
